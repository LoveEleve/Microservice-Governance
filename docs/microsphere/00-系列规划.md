# Microsphere 服务治理系列 · 00 系列规划

> **目标**：用一套文章把 Microsphere 服务治理讲透，而不是按 20 个仓库写 20 篇 README 复述。
> **规模**：**55 篇服务治理主线 + 9 篇附录 + 13 篇数据面 = 77 篇**；统一规划，写作分 A/B 两条线。
> **原则**：问题先行 → 官方基线 → Microsphere 实现 → 正确性/边界 → 我们的实验/决策。**Microsphere 不是正确性标准。**
> **材料**：`docs/microsphere/00-overview`、`01-dimensions`、`02-source-mapping`、`03-source-outline`、`04-method`；Poly 文档作为对照；官方源码作为基线。

---

## 1. 系列定位

Microsphere 是 **Spring / Spring Boot / Spring Cloud 的生产级扩展库集合**，不是从零实现的服务治理框架。它的价值在于：

- 补官方空白：多注册中心、Union Discovery、注册生命周期事件、Feign 动态刷新、多活 Zone；
- 增强默认行为：配置动态化、负载均衡、容错、网关、可观测性；
- 提供可分析的实现样本：用少量类把官方分散的机制收敛出来。

所以文章不能写成“源码翻译”，必须回答：

1. 这个问题官方有没有解？语义是什么？
2. Microsphere 补了什么？假设和代价是什么？
3. 失败、重复、顺序、一致性、性能边界在哪？
4. 我们的项目应该用官方、用 Microsphere，还是自己实现？
