# Microsphere 服务治理系列 · 00 系列规划（42 篇）

> **目标**：吃透 Microservice-Governance 项目本身——源码、设计、边界、实验，而不是铺一套分布式课程。
> **规模**：**42 篇**，服务治理 30 + 数据面 9 + 工程收口 3。
> **原则**：问题先行 → 官方基线 → Microsphere 实现 → 正确性/边界 → 实验/决策。**Microsphere 不是正确性标准。**
> **P7/P8 深度**：不单独开“平台/安全/容量”卷；每篇都写失败语义、规模、迁移/回滚、取舍和面试追问。

---

## 1. 系列定位

Microsphere 是 **Spring / Spring Boot / Spring Cloud 的生产级扩展库集合**，不是从零实现的服务治理框架。项目要讲清：

- 补官方空白：多注册中心、Union Discovery、注册生命周期事件、Feign 动态刷新、多活 Zone；
- 增强默认行为：配置动态化、负载均衡、容错、网关、可观测性；
- 数据面扩展：Redis 复制、MyBatis/Druid 增强、动态数据源、PolyData/PolyCache。

文章不能写成“源码翻译”，每篇必须回答：

1. 这个问题官方有没有解？语义是什么？
2. Microsphere 补了什么？假设和代价是什么？
3. 失败、重复、顺序、一致性、性能边界在哪？
4. 我们的项目应该用官方、用 Microsphere，还是自己实现？

## 4. 每篇固定模板

```text
0. 先看问题 / 反例
1. 分布式 / 微服务原理（只讲本篇需要的）
2. 官方基线（Spring/SCA/Dubbo/官方源码）
3. Microsphere 实现（扩展点、关键类、代码路径）
4. 正确性与边界（失败、重复、顺序、一致性、规模）
5. 我们的实验 / 决策（官方 / Microsphere / 自己实现）
```

P7/P8 深度不靠篇数，靠每篇第 4 节写透：

- 失败语义：超时/部分失败/重试/重复；
- 规模：容量、热点、长尾、成本；
- 迁移：双写、灰度、回滚、对账；
- 取舍：为什么不用官方/为什么不用另一种实现。
