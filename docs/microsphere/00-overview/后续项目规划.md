## 2. 后续项目候选

| 优先级 | 项目 | 补的轴 | 核心内容 | 不做什么 |
|---|---|---|---|---|
| P0 | 可靠消息/事件平台 | 异步可靠性 | 事务消息/Outbox、幂等消费、顺序、延迟、DLQ、重放、积压与背压 | 不只写“使用 RocketMQ/Kafka” |
| P1 | 分布式调度平台 | 批量/弹性 | 分片、worker 注册、leader 选举、rebalance、故障转移、幂等执行、阻塞策略 | 不只写“使用 XXL-Job” |
| P1 | 可观测性平台 | 规模化观测 | 采样、基数、成本、SLO、告警降噪、Trace 上下文 | 不只写“接 Prometheus” |
| P2 | 网关深化 | 入口治理 | 认证、限流、灰度/染色、路由一致性、WebFlux 背压 | 不新建第二个网关项目 |
| P3 | Service Mesh / 控制面 | 基础设施 | xDS、Envoy、sidecar、控制面/数据面 | 成本高，暂不做 |

## 3. 简历组合上限

最多 3 个项目：

1. 服务治理扩展
2. 数据面治理
3. 可靠消息平台

调度/可观测性作为第 4 个备选；网关不单列，深化进服务治理；Mesh 暂不考虑。

## 4. 启动新项目的条件

- 当前 42 篇主线完成 ≥80%；
- 现有项目有可运行 Lab/测试，不是只有读书笔记；
- 新项目必须补一个**不同架构轴**，不能和现有项目重叠；
- 能写出“问题 → 设计 → 失败 → 规模 → 取舍”，否则不值得开。

> 结论：**先吃透已有，再补异步可靠性；不要用项目数量换简历厚度。**
