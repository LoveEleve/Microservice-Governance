# 功能地图（简历与面试主线）

> **定位**：这张表描述“项目支持什么能力、怎么实现、与官方差异是什么”，用于简历与面试；不是缺陷台账。
> **原则**：简历写“能力 + 机制 + 场景”，不写“修复清单”；修复只有形成新能力时才写成“支持 X”。

## 1. 服务治理能力矩阵

| 能力域 | 对外能力 | 核心机制 | 官方基线/差异 | 证据 |
|---|---|---|---|---|
| 多注册中心 | 一个实例同时注册到多个注册中心 | `MultipleServiceRegistry` / `MultipleRegistration`，按 Registration 类型委托 | Spring Cloud 默认单 `ServiceRegistry`；SCA 仅 Nacos；Dubbo 有 service/reference 分离 | 20/21/24 |
| 统一发现 | 跨注册中心聚合实例与服务名 | `UnionDiscoveryClient` 全量并集 | 官方 `CompositeDiscoveryClient` 取第一个非空；语义不同 | 22/24 |
| 注册生命周期 | 注册/注销可观测 | AOP 发布 Pre/Registered/PreDeregistered/Deregistered | 官方缺少同粒度事件 | 23 |
| 动态配置 | 配置加载与运行时刷新 | PropertySource + `EnvironmentChangeEvent` + 刷新边界 | Spring Cloud Config/Refresh 基线 | 26–31 |
| 负载均衡 | 加权、同区域优先、保护阈值 | LoadBalancer + Zone 过滤 + 权重 | 官方 LB 可扩展；Zone 需组合 | 32–33 |
| 多活路由 | Zone 定位、切流、回滚 | ZoneContext + 路由过滤 + 配置切换 | 官方无完整多活抽象 | 37/42 |

| 数据面（Track B） | 动态数据源、分片、Redis 多机房 | PolyData / PolyCache / MyBatis / Druid | 纳入同一系列规划；写作与简历单独成线 | B01–B06 |

## 2. 简历写法（功能视角）

### 版本 A：服务治理主线

- **多注册中心**：支持一个服务实例同时注册到 Nacos/Eureka 等异构注册中心，基于 `ServiceRegistry/Registration` 扩展点按注册类型委托；解决双注册迁移中的重复注册、部分失败和实例去重边界。
- **统一发现**：提供跨注册中心的实例/服务名聚合，区分官方 `CompositeDiscoveryClient` 的“第一个非空”语义与全量并集语义，支持空结果、重复实例和元数据冲突处理。
- **注册生命周期**：支持注册/注销 Pre/Post 事件，覆盖注册状态变化，便于观测和故障定位。
- **动态配置**：支持配置加载与运行时刷新，区分属性级刷新与 Bean/Feign 组件重建，明确刷新风暴、旧值、回滚边界。
- **负载均衡与多活**：支持加权轮询、同区域优先、最小可用数/就绪率保护，以及配置中心驱动的秒级切流与回滚。
- **容错治理**：支持限流、熔断、重试、隔离，明确重试放大、熔断误判、降级边界。
- **网关治理**：支持动态路由、服务发现接入、路由刷新与端点级控制。
- **可观测性**：支持注册/配置/路由/Zone 关键状态的指标、日志与健康检查。

### 版本 B：数据面项目（与 A 线并列，不混写）

- **PolyData**：支持动态多数据源、子上下文隔离、热替换、同区域优先、故障转移、MyBatis/MyBatis-Plus 并存、ShardingSphere。
- **PolyCache**：支持 Redis 多机房命令级复制、Kafka 分区保序、语义重放、回环防护、动态连接切换。

## 3. 使用规则

1. 服务治理与数据面统一规划，但写作/简历分成 A/B 两条线；
2. 简历只写“对外能力 + 关键机制 + 场景”，不写“修复清单”；
3. 每条至少能回答一个“为什么难/边界在哪”；
4. 修复台账（`06-production`）只用于内部工程，不直接进简历；
5. 如果某个修复形成了新能力，改写成“支持 X 场景”，不写“修了 Y bug”。
