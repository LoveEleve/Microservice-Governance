# 架构约束

## 1. 消息层

```text
Redis List
一条事件一个业务线 List
一个逻辑消费者
不使用消费者组
不做 fan-out
不使用 Kafka/RocketMQ/Stream
```

## 2. 数据层

```text
MySQL 是正本
Redis 是可重放缓冲
payload 不能只在 Redis
TCC 状态只在 MySQL
```

## 3. 生产形态

```text
ShardingSphere 16×4=64
读写分离：写主库，查询走从库
主从延迟 > 500ms 回主库
Nacos 注册/配置
Sentinel 流控/熔断
Redis Cluster 3 主 3 从
协调器 5 实例
```

## 4. 禁止

```text
production=false 的单库代码路径
绕过 ShardingSphere 拼物理表
消息/幂等 SQL 不带分片键
把消费者组概念引入设计
把 TCC 状态放 Redis
```

## 5. 允许

```text
测试用单实例 fixture
测试用 mock Nacos/Sentinel
不真实启动集群
但代码路径、分片键、路由规则保持生产形态
```
