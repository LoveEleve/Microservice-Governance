## P1

```text
Participant Starter 为什么需要显式扫描 BarrierMapper？
Nacos 配置热更新怎么验证？

分支注册职责错位
  当前 TM 的 @TccBranch 先 registerBranch，再调 RM Try。
  actionName/resourceKey/callbackEndpoint/applicationData 都在 TM。
  目标：RM 在 Try 入口自注册，TM 只负责 begin 和调用 Try。
  详细讨论：docs/07-学习讨论/09-2026-11-08-分支注册职责讨论.md

TM 配置 RM callbackEndpoint 的耦合
  当前 @TccBranch 必须写 callbackEndpoint，TC 从 branch 行读取。
  TM 知道了 RM 的部署地址，边界不干净。
  目标：RM 启动时把 serviceName/endpoint 注册到 TC 或注册中心，
  TM 只给 actionName/resourceKey，TC 解析 callback。

AOP 代理和 @EnableAspectJAutoProxy 入口不透明
  LeadAssignService、quotaGateway、couponGateway 当前都是 Spring AOP 代理：
    LeadAssignService -> @TccTransactional
    quotaGateway/couponGateway -> @TccBranch
  @EnableAspectJAutoProxy 在 starter 的 TccAnnotationAutoConfiguration 上，
  业务应用代码里看不到，容易误以为没有开启。
  当前强制 proxyTargetClass=true，可能覆盖用户的 AOP 配置。
  待定：依赖 Boot AopAutoConfiguration，或提供 proxy-target-class 开关并写清文档。
```
