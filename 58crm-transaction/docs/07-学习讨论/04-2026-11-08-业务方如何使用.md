# 2026-11-08 业务方如何使用

> ⚠️ 历史说明：本文最初展示的是 E2E 裸协议验证代码。
> 公共 SDK 已落地，最新接入方式见 `QUICKSTART.md` 和 `docs/02-设计/33-TCC公开API与SDK重构规划.md`。
> 深度问题见 `docs/04-验证/16-Framework-Access-Review.md`。

> 本课目标：知道一个业务方接入 TCC 时需要写什么、框架替你做什么、哪里不能偷懒。

## 1. 先看例子

场景：

```text
lead-service 分配线索
  -> 扣减 quota-service 的额度
```

成功：

```text
quota reserved + 1      Try
quota assigned + 1      Confirm
Outbox 写 QUOTA_CONFIRMED
```

失败：

```text
quota Try 失败
  -> TC rollback
  -> quota Cancel
  -> barrier SUSPENDED（空回滚）
```

## 2. 两个角色

```text
TM（业务方）：lead-service
  发起全局事务、注册分支、调用 Try、上报结果、commit/rollback

RM（参与方）：quota-service
  实现 TccAction、barrier、Try HTTP 接口、Confirm/Cancel gRPC callback
```

## 3. RM：实现 TccAction

完整代码：

```java
public class QuotaTccAction implements TccAction {

    private final QuotaMapper quotaMapper;
    private final OutboxPublisher outboxPublisher;

    public QuotaTccAction(QuotaMapper quotaMapper, OutboxPublisher outboxPublisher) {
        this.quotaMapper = quotaMapper;
        this.outboxPublisher = outboxPublisher;
    }

    @Override
    public TccTryResult tryAction(BusinessActionContext context) {
        return quotaMapper.reserve(userId(context)) == 1
                ? TccTryResult.SUCCESS : TccTryResult.FAILURE;
    }

    @Override
    public TccPhaseResult confirmAction(BusinessActionContext context) {
        long userId = userId(context);
        if (quotaMapper.confirm(userId) != 1) {
            return TccPhaseResult.PERMANENT_FAILURE;
        }
        outboxPublisher.publish(new BusinessEvent(
                "quota-confirmed:" + context.xid() + ":" + context.branchId(),
                "quota",
                String.valueOf(userId),
                "QUOTA_CONFIRMED",
                "{\"userId\":" + userId + "}"));
        return TccPhaseResult.SUCCESS;
    }

    @Override
    public TccPhaseResult cancelAction(BusinessActionContext context) {
        return quotaMapper.cancel(userId(context)) == 1
                ? TccPhaseResult.SUCCESS : TccPhaseResult.PERMANENT_FAILURE;
    }

    private long userId(BusinessActionContext context) {
        String data = context.applicationData();
        String number = data.replaceAll("[^0-9]", "");
        if (number.isEmpty()) {
            throw new IllegalArgumentException("userId missing: " + data);
        }
        return Long.parseLong(number);
    }
}
```

注意：

```text
tryAction     只预占，不写终态
confirmAction 写终态 + Outbox
cancelAction  释放预占
三个方法都要考虑重复执行
```

## 4. RM：注册 action

```java
@Component
public class QuotaActionRegistration {

    public QuotaActionRegistration(
            TccActionRegistry registry,
            QuotaTccAction action) {
        registry.register("reserveQuota", action);
    }
}
```

`actionName` 必须和 TM 注册分支时的 `actionName` 一致：

```text
reserveQuota
```

## 5. RM：暴露 Try 接口

框架不替业务发起 Try，Try 是业务 API：

```java
@RestController
public class QuotaController {

    private final TccParticipantService participantService;

    public QuotaController(TccParticipantService participantService) {
        this.participantService = participantService;
    }

    @PostMapping("/quota/try")
    public TryQuotaResponse tryQuota(@RequestBody TryQuotaRequest request) {
        TccTryResult result = participantService.tryAction(new BusinessActionContext(
                request.xid(),
                request.branchId(),
                "reserveQuota",
                "{\"userId\":" + request.userId() + "}"));
        return new TryQuotaResponse(
                result == TccTryResult.SUCCESS,
                result.name());
    }
}
```

这里 `TccParticipantService.tryAction` 会：

```text
1. 查/插 barrier
2. 调 QuotaTccAction.tryAction
3. 同一事务提交
4. Try 失败自动 rollback-only
```

## 7. TM：发起 TCC

完整代码：

```java
@Service
public class LeadAssignService {

    private final TccCoordinatorClient coordinator;
    private final QuotaFeignClient quotaClient;
    private final String quotaCallbackEndpoint;

    public LeadAssignService(
            TccCoordinatorClient coordinator,
            QuotaFeignClient quotaClient,
            @Value("${quota.callback-endpoint:127.0.0.1:9092}")
            String quotaCallbackEndpoint) {
        this.coordinator = coordinator;
        this.quotaClient = quotaClient;
        this.quotaCallbackEndpoint = quotaCallbackEndpoint;
    }

    public AssignResult assign(long leadId, long userId) {
        String requestId = "lead-" + leadId + "-" + userId + "-" + UUID.randomUUID();
        BeginResponse begin = coordinator.begin(BeginRequest.newBuilder()
                .setRequestId(requestId)
                .setBizCode("lead")
                .setBizId(String.valueOf(leadId))
                .setTryTimeoutSeconds(30)
                .build());
        long xid = begin.getXid();

        try {
            RegisterBranchResponse branch = coordinator.registerBranch(
                    RegisterBranchRequest.newBuilder()
                            .setXid(xid)
                            .setResourceKey("quota:" + userId)
                            .setActionName("reserveQuota")
                            .setCallbackEndpoint(quotaCallbackEndpoint)
                            .setApplicationData("{\"userId\":" + userId + "}")
                            .build());

            TryQuotaResponse tryResponse = quotaClient.tryQuota(
                    new TryQuotaRequest(xid, branch.getBranchId(), userId));
            if (!tryResponse.success()) {
                coordinator.report(xid, branch.getBranchId(), BranchStatus.BRANCH_TRY_FAIL);
                coordinator.rollback(xid);
                return new AssignResult(xid, "TRY_FAIL");
            }

            coordinator.report(xid, branch.getBranchId(), BranchStatus.BRANCH_TRY_SUCCESS);
            CommitResponse commit = coordinator.commit(xid);
            return new AssignResult(xid, commit.getStatus().name());
        } catch (RuntimeException failure) {
            try {
                coordinator.rollback(xid);
            } catch (RuntimeException ignored) {
                // 保留原始异常
            }
            throw failure;
        }
    }
}
```

顺序不能变：

```text
begin
registerBranch
try
report
commit / rollback
```

## 8. OpenFeign 的 Try

```java
@FeignClient(name = "quota-service")
public interface QuotaFeignClient {

    @PostMapping("/quota/try")
    TryQuotaResponse tryQuota(@RequestBody TryQuotaRequest request);
}
```

协议边界：

```text
TM -> RM Try：OpenFeign
TM -> TC：gRPC
TC -> RM Confirm/Cancel：gRPC callback
```

TC 不通过 OpenFeign 调 RM，因为 TC 不发现 RM，且 callback 是 gRPC 契约。

## 9. 业务方最容易犯的错

```text
1. 忘记 registerBranch 就直接 Try
2. Try 成功不上报 TRY_SUCCESS
3. 业务异常不 rollback
4. requestId 每次变化，无法做业务幂等
5. callbackEndpoint 配成 Pod IP / 不可达地址
6. Confirm 里不写 Outbox，或 Outbox 不在同一事务
7. TccAction 三个方法不做幂等
8. 以为框架会自动生成业务事件
```

## 10. 接入检查清单

```text
RM：
  TccAction 实现
  actionName 注册
  Try HTTP/gRPC 业务接口
  BarrierMapper 扫描
  callback gRPC server 端口
  业务表 + barrier + outbox 同库/同事务

TM：
  Coordinator gRPC 客户端
  begin / register / try / report / commit
  失败 rollback
  requestId 业务幂等键
  下游 Try 的 OpenFeign 客户端
```

## 11. 一句话

> **业务方负责 Try 和业务语义；框架负责全局状态、branch、barrier 和 Confirm/Cancel 调度。**
