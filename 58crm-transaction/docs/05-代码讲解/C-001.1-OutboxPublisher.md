## 3. 类清单

| 类 | 作用 |
|---|---|
| `BusinessEvent` | 业务事件，只描述发生了什么 |
| `OutboxPublisher` | 业务方发布事件的接口 |
| `MybatisOutboxPublisher` | 把事件写成 INIT 消息 |
| `LocalMessageEntity` | `t_local_message` 的 MyBatis-Plus 映射 |
| `LocalMessageMapper` | `BaseMapper`，当前只使用 `insert` |
| `LocalMessage` | 消息领域视图，供后续消费侧读取 |
| `MessageStatus` | INIT/SENT/PROCESSING/CONSUMED/DEAD |

## 4. 业务事件

```java
public record BusinessEvent(
        String eventKey,
        String bizCode,
        String bizId,
        String eventType,
        String payload) {
}
```

字段含义：

```text
eventKey   事件唯一键，防重复
bizCode    业务编码，后续作为 Redis List 路由键
bizId      业务单号，消息表分片键
eventType  事件类型
payload    事件正文
```

校验：

```text
eventKey / bizCode / bizId / eventType 不能为空
payload 不能为 null
```

## 5. 发布实现

```java
public class MybatisOutboxPublisher implements OutboxPublisher {

    private final LocalMessageMapper localMessageMapper;

    @Override
    @Transactional(propagation = Propagation.MANDATORY)
    public String publish(BusinessEvent event) {
        String msgId = UUID.randomUUID().toString();
        LocalDateTime now = LocalDateTime.now();

        LocalMessageEntity entity = new LocalMessageEntity();
        entity.setMsgId(msgId);
        entity.setEventKey(event.eventKey());
        entity.setBizCode(event.bizCode());
        entity.setBizId(event.bizId());
        entity.setEventType(event.eventType());
        entity.setPayload(event.payload());
        entity.setStatus(MessageStatus.INIT.name());
        entity.setRetryCount(0);
        entity.setCreatedAt(now);
        entity.setUpdatedAt(now);

        localMessageMapper.insert(entity);
        return msgId;
    }
}
```

## 6. 为什么是 MANDATORY

```java
@Transactional(propagation = Propagation.MANDATORY)
```

含义：

```text
调用方必须已经开启事务
没有事务就抛异常
```

如果写成 `REQUIRED`：

```text
业务方忘开事务
publish 自己开一个新事务
消息先提交
业务后回滚
→ 消息存在，业务没成功
```

所以这里强制要求业务方把：

```text
业务表更新
+ t_local_message 插入
```

放进同一个本地事务。

## 7. 为什么状态是 INIT

```text
INIT = 已写 MySQL，还没投递 Redis
```

不能直接写 `SENT`：

```text
写 SENT 代表已经投递成功
但 publish 阶段还没碰 Redis
```

后续 Relay 才做：

```text
INIT
  → LPUSH tx:queue:{bizCode}
  → SENT
```

## 8. 为什么这里没有 Redis

```text
Redis 不是正本
publish 只负责“消息一定落 MySQL”
Relay 才负责“尽快送 Redis”
```

如果 publish 里直接写 Redis：

```text
Redis 抖动会阻塞业务事务
Redis 成功、MySQL 回滚会产生幽灵消息
无法保证业务数据和消息同事务
```
