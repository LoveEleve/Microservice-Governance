# 生产者全链路图

> 从业务提交，到消息进入 Redis Stream，再到 MySQL 状态更新。
> 场景：线索 lead-1 分配给销售 1001。

## 2. 业务方实际代码

```java
@Transactional
public void assignLead(AssignLeadCommand command) {
    // 1. 业务表更新
    leadRepository.assign(command.leadId(), command.salesId());

    // 2. 同一个本地事务写 Outbox
    outboxPublisher.publish(new BusinessEvent(
        "lead-assigned:" + command.leadId() + ":" + command.requestId(),
        "lead",
        String.valueOf(command.leadId()),
        "LEAD_ASSIGNED",
        "{\"leadId\":" + command.leadId()
                + ",\"salesId\":" + command.salesId() + "}"
    ));
}
```

## 3. 生产阶段

```text
业务服务
  → @Transactional
  → 业务表写
  → OutboxPublisher.publish
  → t_local_message(INIT)
  → COMMIT
```

生产阶段不碰 Redis。

## 4. 扫描阶段

```text
OutboxScanner
  → 按 bizCode 轮询
  → 每业务线 perBizLimit
  → tryPut 到 OutboxBuffer
```

扫描阶段只做：

```text
MySQL -> 内存队列
```

## 5. 发送阶段

```text
OutboxSender
  → 只处理 assignedBizCodes
  → 10ms linger
  → 最多 256 条
  → 拦截器/路由/序列化
  → XADD pipeline
  → markSentBatch
```

## 6. 状态变化

```text
业务事务 COMMIT:
  t_local_message = INIT

XADD 成功:
  t_local_message = SENT
  stream_entry_id = 179...-0

对账确认消费方 CONSUMED:
  t_local_message = DONE
```

## 7. 失败路径

```text
XADD 失败
  → INIT + retry_count + next_retry_at
  → Scanner 到期重试
  → 超过 maxRetries -> DEAD

per-biz buffer 满
  → tryPut=false
  → 该业务线本轮跳过
  → 下一轮再扫

未知 bizCode
  → 发布时拒绝
  → 不创建孤儿 Stream
```

## 8. 关键边界

```text
业务表和 t_local_message 同事务
Redis 只是传输，不是正本
Scanner 不直接 XADD
Sender 不直接扫 MySQL
一个 bizCode 一个 Stream
一个 bizCode 一个内存队列
一个 bizCode 只属于一个 Sender shard
```
