# 生产端类与方法全解

> **业务方先看：`docs/01-使用/02-生产端接入手册.md`。**  
> 读完本文你能做什么：知道每个类负责什么、每个公开方法/关键私有方法做什么、失败会怎样。
> 范围：`crm-tx-outbox` 生产端；消费端尚未实现。

## 1. api

### `BusinessEvent`

作用：

```text
业务方要发布的一条领域事件
```

字段：

```text
eventKey   事件唯一键，业务幂等
bizCode    业务线，决定 Stream key
bizId      业务单号，MySQL 分片键
eventType  事件类型
payload    事件正文
```

方法：

| 方法 | 说明 |
|---|---|
| `BusinessEvent(...)` | 校验 eventKey/bizCode/bizId/eventType 非空，payload 不能 null |
| `eventKey()` | record accessor |
| `bizCode()` | record accessor |
| `bizId()` | record accessor |
| `eventType()` | record accessor |
| `payload()` | record accessor |

### `OutboxPublisher`

作用：

```text
业务方唯一依赖的发布接口
```

| 方法 | 说明 |
|---|---|
| `publish(BusinessEvent)` | 在当前本地事务中写一条 INIT 消息，返回 msgId |

实现必须满足：

```text
调用方已经在事务中
只写 MySQL，不写 Redis
```

## 2. config

### `BizCodeConfig`

作用：

```text
生产端允许发布的业务线白名单项
```

| 方法 | 说明 |
|---|---|
| `BizCodeConfig(String bizCode)` | 校验 bizCode 非空 |
| `bizCode()` | 返回业务编码 |

注意：

```text
这里没有 consumers
消费并发属于 ConsumerConfig
```

### `BizCodeRegistry`

作用：

```text
bizCode 白名单 + stream key 推导
```

| 方法 | 说明 |
|---|---|
| `BizCodeRegistry(Collection<BizCodeConfig>)` | 构建注册表，拒绝空集合和重复 bizCode |
| `from(Map<String,BizCodeConfig>)` | 从外部配置构建，校验 map key 与 config.bizCode 一致 |
| `of(String...)` | 测试/最小示例的便捷构造 |
| `require(String)` | 校验并返回配置；未知抛 `UnknownBizCodeException` |
| `contains(String)` | 是否注册 |
| `bizCodes()` | 全部合法 bizCode |
| `streamKey(prefix,bizCode)` | 返回 `prefix + bizCode`，同时校验白名单 |

### `UnknownBizCodeException`

| 方法 | 说明 |
|---|---|
| `UnknownBizCodeException(String)` | 携带未知 bizCode 的运行时异常 |

## 3. domain

### `LocalMessage`

生产端消息领域视图（不是 ORM 实体）。

| 方法 | 说明 |
|---|---|
| `LocalMessage(...)` | 校验 msgId/eventKey/bizCode/bizId/eventType/status，payload 或 payloadRef 至少一个；包含 streamEntryId |
| `msgId()` | 返回消息 ID |
| `eventKey()` | 返回业务事件键 |
| `bizCode()` | 返回业务线 |
| `bizId()` | 返回业务单号 |
| `eventType()` | 返回事件类型 |
| `payload()` | 返回正文 |
| `payloadRef()` | 返回大对象引用 |
| `status()` | 返回生产方状态 |
| `retryCount()` | 返回重试次数 |

### `OutboxRecord`

发送线程使用的不可变记录。

| 方法 | 说明 |
|---|---|
| `OutboxRecord(...)` | 同 `LocalMessage` 的基础校验 |
| `from(LocalMessage)` | 把数据库视图转换成发送记录 |
| `toLocalMessage()` | 反向转换，供状态回写 |
| `msgId()` | 返回消息 ID |
| `eventKey()` | 返回业务事件键 |
| `bizCode()` | 返回业务线 |
| `bizId()` | 返回业务单号 |
| `eventType()` | 返回事件类型 |
| `payload()` | 返回正文 |
| `payloadRef()` | 返回大对象引用 |
| `status()` | 返回当前状态 |
| `retryCount()` | 返回重试次数 |

### `OutboxSendResult`

| 方法 | 说明 |
|---|---|
| `OutboxSendResult(stream,msgId,entryId)` | 发送结果元数据 |
| `stream()` | 返回 Stream key |
| `msgId()` | 返回消息 ID |
| `entryId()` | 返回 Stream entry ID（当前可为 null） |

`entryId` 当前未从 pipeline 结果中回填，后续可扩展。

## 4. persistence

### `LocalMessageEntity`

MyBatis-Plus 实体，映射 `t_local_message`。

字段：

```text
msgId / eventKey / bizCode / bizId / eventType
payload / payloadRef / status
retryCount / nextRetryAt / createdAt / updatedAt
```

方法：

| 字段 | getter | setter |
|---|---|---|
| msgId | `getMsgId()` | `setMsgId()` |
| eventKey | `getEventKey()` | `setEventKey()` |
| bizCode | `getBizCode()` | `setBizCode()` |
| bizId | `getBizId()` | `setBizId()` |
| eventType | `getEventType()` | `setEventType()` |
| payload | `getPayload()` | `setPayload()` |
| payloadRef | `getPayloadRef()` | `setPayloadRef()` |
| status | `getStatus()` | `setStatus()` |
| retryCount | `getRetryCount()` | `setRetryCount()` |
| nextRetryAt | `getNextRetryAt()` | `setNextRetryAt()` |
| createdAt | `getCreatedAt()` | `setCreatedAt()` |
| updatedAt | `getUpdatedAt()` | `setUpdatedAt()` |

这些方法只做字段读写，不包含业务判断。

### `LocalMessageMapper`

```java
extends BaseMapper<LocalMessageEntity>
```

当前使用：

```text
insert
selectList
selectById
update
```

其余 `BaseMapper` 方法继承但当前未使用。

### `LocalMessageRepository`

生产端仓储接口。

| 方法 | 说明 |
|---|---|
| `findRelayCandidates(int limit)` | 兼容旧接口：全局查 INIT（Scanner 已不使用） |
| `findRelayCandidatesByBizCode(bizCode,limit)` | 按业务线查 INIT，供公平轮询 |
| `markSentBatch(List, Instant)` | 批量 INIT -> SENT（兼容旧调用） |
| `markSentBatch(List, Instant, Map)` | 批量 INIT -> SENT，并写 stream_entry_id |
| `markFailedBatch(List, Instant, int)` | 批量失败重试；达到 maxRetries 转 DEAD |
| `markDoneBatch(List)` | 对账确认消费后 SENT -> DONE |
| `findForReconcile(Instant,int)` | 查询 SENT 对账候选 |

### `MybatisLocalMessageRepository`

| 方法 | 说明 |
|---|---|
| `MybatisLocalMessageRepository(LocalMessageMapper)` | 构造 |
| `findRelayCandidates(limit)` | 按状态+next_retry_at 查询，limit 限制 1~1000 |
| `markSentBatch(messages,nextRetryAt)` | 按 bizId 分组批量 UPDATE，INIT -> SENT |
| `markFailedBatch(messages,nextRetryAt,maxRetries)` | 按 bizId 分组 UPDATE，retry_count+1，超限 DEAD |
| `toDomain(entity)` | Entity -> LocalMessage |
| `toLocalDateTime(Instant)` | Instant -> LocalDateTime |

### `MybatisOutboxPublisher`

| 方法 | 说明 |
|---|---|
| `MybatisOutboxPublisher(mapper, registry)` | 构造 |
| `publish(event)` | 校验 bizCode -> 生成 msgId -> 插入 INIT 消息，返回 msgId |

事务：

```text
@Transactional(propagation = MANDATORY)
调用方必须有本地事务
```

## 5. producer

### `OutboxConfig`

生产端运行时参数。

字段：

```text
streamPrefix
linger
batchSize
bufferCapacity
bufferCapacityBytes
scanBatch
scanInterval
retryAfter
maxRetries
senderThreads
```

| 方法 | 说明 |
|---|---|
| `OutboxConfig(...)` | 校验正数参数 |
| `defaults()` | 10ms linger / 256 batch / 50k 条 / 64MB / 10ms scan / 30s retry / 5 retries / 8 senders |
| `streamPrefix()` | Stream key 前缀 |
| `linger()` | 聚合窗口 |
| `batchSize()` | 单批上限 |
| `bufferCapacity()` | buffer 条数上限 |
| `bufferCapacityBytes()` | buffer 字节上限 |
| `scanBatch()` | 单轮扫描条数 |
| `scanInterval()` | 扫描周期 |
| `retryAfter()` | 失败下次重试间隔 |
| `maxRetries()` | 最大重试次数 |
| `senderThreads()` | Sender shard 上限 |
| `requirePositive(...)` | Duration 正数校验 |

### `OutboxBuffer`

按 bizCode 分桶的有界内存 buffer。

| 方法 | 说明 |
|---|---|
| `OutboxBuffer(maxMessages,maxBytes)` | 构造并校验容量 |
| `put(record)` | 入队；全局/单业务线满时阻塞；单条超 maxBytes 抛 `MessageTooLargeException` |
| `tryPut(record)` | 非阻塞；单个业务线满返回 false，Scanner 跳过该业务线 |
| `poll(Duration)` | 从任意业务线取一条 |
| `poll(Set<String>,Duration)` | 从指定业务线集合取一条（Sender shard 使用） |
| `poll(String,Duration)` | 从指定业务线取一条（linger 聚合使用） |
| `drain(bizCode,target,maxElements)` | 批量取指定业务线 |
| `size()` | 当前条数 |
| `remainingCapacity()` | 剩余条数容量 |
| `removeOneLocked()` | 内部：从 ready 头取一条并维护计数 |
| `estimateBytes(record)` | 估算 payload/payloadRef 字节，用于背压 |
| `deadlineNanos(timeout)` | 计算等待截止时间 |

并发规则：

```text
queues / ready / count / bytes 都由同一把 ReentrantLock 保护
```

### `OutboxInFlight`

| 方法 | 说明 |
|---|---|
| `add(msgId)` | 加入 in-flight，返回 false 表示已存在 |
| `remove(msgId)` | 释放 |
| `size()` | 当前 in-flight 数 |

### `OutboxScanner`

| 方法 | 说明 |
|---|---|
| `OutboxScanner(repo,buffer,inFlight,scanBatch,registry)` | 构造，内部维护 bizCode 轮询 cursor |
| `scanOnce()` | 按注册 bizCode 轮询扫描 INIT，每个业务线有配额；未知/超大直接 DEAD |
| `reject(candidate)` | 内部：inFlight 释放 + `markFailedBatch(maxRetries=1)` |

### `OutboxSender`

| 方法 | 说明 |
|---|---|
| `OutboxSender(...)` | 绑定 buffer、publisher、拦截器、路由、序列化、repository、in-flight、assignedBizCodes |
| `sendOnce()` | 取一批 -> 拦截器 -> 路由 -> 序列化 -> XADD -> markSent |
| `publishOrSplit(stream,records,...)` | 整批失败时二分拆批，隔离 poison 消息 |
| `publishFailed(records,nextRetry,error)` | 通知拦截器 + markFailedBatch |
| `originalsOf(records,map)` | 防止拦截器改 msgId 后回写错行 |
| `toLocalMessages(records)` | record -> LocalMessage |

状态：

```text
INIT -> SENT（XADD 成功）
INIT -> INIT/SENT（失败重试）
超过 maxRetries -> DEAD
```

### `SenderAssignment`

| 方法 | 说明 |
|---|---|
| `assign(bizCodes, senderThreads)` | 排序后轮询分配；shardCount = min(threads,bizCount) |

返回：

```text
Map<shardIndex, Set<bizCode>>
```

### `OutboxProducerFactory`

| 方法 | 说明 |
|---|---|
| `create(buffer,publisher,interceptors,partitioner,serializer,repo,inFlight,config,registry)` | 推荐入口；内部按 config.scanBatch 创建 Scanner |
| `create(scanner,buffer,...)` | 兼容入口；调用方自己提供 Scanner |

### `OutboxProducer`

| 方法 | 说明 |
|---|---|
| `OutboxProducer(scanner,sender,...)` | 单 Sender 兼容构造 |
| `OutboxProducer(scanner,senders,...)` | 多 Sender shard 构造 |
| `start()` | 启动 scanner 调度 + sender 线程池；重复启动抛异常 |
| `senderCount()` | 实际 Sender 数 |
| `scanSafely()` | 内部：单轮扫描异常不杀线程 |
| `sendLoop(sender)` | 内部：单 Sender 循环，异常不杀线程 |
| `close()` | 停止线程池，等待 Sender 5 秒，关闭拦截器 |

### `MessageTooLargeException`

| 方法 | 说明 |
|---|---|
| `MessageTooLargeException(msgId,bytes,maxBytes)` | 单条消息超过 buffer 字节上限 |

## 6. pipeline

### `OutboxInterceptor`

| 方法 | 说明 |
|---|---|
| `onSend(record)` | 发送前；可返回新 record |
| `onAcknowledgement(result,error)` | 发送成功/失败后；必须快 |
| `close()` | 默认空实现；释放资源时调用 |

### `OutboxInterceptorChain`

| 方法 | 说明 |
|---|---|
| `OutboxInterceptorChain(List)` | 复制有序拦截器列表 |
| `onSend(record)` | 顺序执行，异常隔离，null 视为不修改 |
| `onAcknowledgement(result,error)` | 顺序回调，异常隔离 |
| `close()` | 逆序/顺序关闭（当前顺序），异常隔离 |

### `OutboxPartitioner` / `BizCodePartitioner`

| 方法 | 说明 |
|---|---|
| `route(record)` | 返回业务线路由值；默认 `record.bizCode()` |

### `OutboxSerializer` / `DefaultOutboxSerializer`

| 方法 | 说明 |
|---|---|
| `serialize(record)` | record -> Stream field map |
| `Default...` | 输出 msgId/eventKey/bizCode/bizId/eventType/payload/payloadRef |

### `RedisStreamPublisher` / `RedisStreamPublisherAdapter`

| 方法 | 说明 |
|---|---|
| `publish(stream,records)` | 批量 XADD |
| `RedisStreamPublisherAdapter(StringRedisTemplate)` | 构造 |
| `publish(...)` | `executePipelined` 一次提交多条 XADD，并检查结果数/null |
