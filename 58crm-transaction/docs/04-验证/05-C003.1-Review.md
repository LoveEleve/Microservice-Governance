## 2. 发现与处理

### P0：XID 号段分配器非原子（已修）

```text
JdbcSegmentAllocator:
  UPDATE ...
  SELECT ...
两条 SQL、两次连接
```

后果：

```text
并发 TC 可能拿到重叠号段
XID 重复
```

处理：

```text
项目内新增 crm-tx-tcc-id
改用 MyBatis-Plus + @Transactional(REQUIRES_NEW)
UPDATE 和 SELECT 在同一连接/事务内
补 8 线程并发测试和回滚隔离测试
```

详细设计见 `22-TCC-号段ID.md`。

### P0：Commit/Rollback 崩溃恢复窗口（已修设计）

原设计：

```text
Commit 只改 global -> CONFIRMING
branch 仍 TRY_SUCCESS
```

问题：

```text
Scheduler 只扫 branch CONFIRMING/CANCELLING
branch 停在 TRY_SUCCESS 永远扫不到
global 卡死
```

修正：

```text
Commit 同一事务:
  branch TRY_SUCCESS -> CONFIRMING
  branch.next_retry_at = NOW(3)
  global TRYING -> CONFIRMING

Rollback 同一事务:
  branch TRYING/TRY_SUCCESS/TRY_FAIL -> CANCELLING
  branch.next_retry_at = NOW(3)
  global TRYING -> CANCELLING
```

### P1：branch Confirm 成功缺少 global 状态条件（已修设计）

原 SQL：

```text
WHERE branch.status = 'CONFIRMING'
  AND owner_token = ?
```

问题：

```text
global 已 FAILED 后，旧 owner 仍可能把 branch 改成 CONFIRMED
```

修正：

```text
增加 g.status = 'CONFIRMING'
```

Cancel 同样必须带 `g.status='CANCELLING'`。

### P1：ReportBranch 被误写成 owner fencing 例外（已澄清）

```text
ReportBranch:
  只允许 global TRYING
  只允许 branch TRYING -> TRY_SUCCESS/TRY_FAIL
  不是二阶段推进
  不加 owner
```

所有 Confirm/Cancel/DEAD/终态更新仍然必须带 owner。

### P1：重复 RegisterBranch 冲突语义缺失（已补设计）

```text
同 resourceKey：
  actionName/callbackEndpoint 相同 -> 返回已有 branch
  actionName/callbackEndpoint 不同 -> TCC_INVALID_STATE
```

不能静默返回旧 branch，否则 Confirm 可能打到错误 endpoint。

### P1：空分支语义缺失（已补设计）

```text
Commit 无 branch -> TCC_NOT_READY
Rollback 无 branch -> CANCELLED
```

不允许把“没有参与方”的事务当成业务确认成功。

### P1：FAILED/DEAD 文档仍有“人工/告警”残留（已修）

修正：

```text
AH / AM / M / AA / Review 2
统一为 DEAD -> global FAILED -> ERROR 日志
不做告警平台/管理台/人工重放
```

### P2：proto 超时类型不一致（已修）

Java DTO：

```text
int tryTimeoutSeconds
```

proto 原为：

```text
int64 try_timeout_seconds
```

已改为：

```text
int32 try_timeout_seconds
```

### P2：proto 尚未 codegen（保留到 C-003.2）

当前只放：

未接入 protobuf-maven-plugin，因此：

```text

```
