# 验证与测试

> 读完你能做什么：知道每个 AC 对应哪个测试，怎么证明代码不是“看起来对”。

## 1. 测试层次

```text
单元测试
  状态机、幂等、重试、空回滚/悬挂

集成测试
  MySQL Outbox → Buffer → Redis Stream → Consumer

故障测试
  Redis 丢消息、消费者崩溃、重复投递、主从延迟
```

## 2. C-001 验收条件

```text
AC1 业务事务成功 → t_local_message(INIT)
AC2 业务事务失败 → 没有消息
AC3 Relay 扫描 → LPUSH 业务线 List → SENT
AC4 消费成功 → t_consume_record(CONSUMED) → XACK
AC5 消费者崩溃 → PEL + XCLAIM/XAUTOCLAIM 重试
AC6 重复投递 → msg_id + biz_key 幂等；重复 ACK 幂等
AC7 Redis 丢消息 → MySQL INIT 重放/独立重建
AC8 同一事件不 fan-out 到多个队列
```

## 4. 当前测试命令

默认只跑单元/H2：

```text
mvn -pl crm-tx-outbox -am test
```

真实 MySQL + Redis Stream 集成测试需要显式开启：

```bash
mvn -pl crm-tx-outbox -am test   -Dtx.it=true   -Dtx.mysql.password=<local-password>
```

可用参数：

```text
tx.it=true
tx.mysql.host
tx.mysql.port
tx.mysql.user
tx.mysql.password
tx.redis.host
tx.redis.port
```

测试不会把密码写进仓库。

## 5. 每次变更门禁

```text
编译通过
单测通过
集成测试通过
静态检查通过
change.md 的 AC 全部有测试
```

## 6. 不做什么

```text
不要求真实启动 64 个库
不要求真实启动 Redis Cluster
不要求真实启动 Nacos/Sentinel
```

但代码必须走生产路由：

```text
ShardingSphere 逻辑表
分片键
读写分离
幂等键
```
