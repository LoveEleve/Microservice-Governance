# C-004.4 Review

> 审查对象：独立 TCC Starter。
> 结论：TCC 已从通用 Starter 拆出；client/participant 可独立开关。

## 1. 新模块

```text
crm-tx-tcc-spring-boot-starter
  CrmTxTccProperties
  CrmTxTccClientAutoConfiguration
  CrmTxTccParticipantAutoConfiguration
  CrmTxTccBarrierMapperConfiguration
```

## 1.1 P0：client/participant 默认同时开启

问题：

```text
TM-only 应用会被 participant 自动装配拖死
RM-only 应用会被 client 自动装配拖死
```

修复：

```text
crm.tx.tcc.client.enabled 默认 false
crm.tx.tcc.participant.enabled 默认 false
使用哪一侧，显式开启哪一侧
```

## 2. 配置

```yaml
crm:
  tx:
    tcc:
      client:
        enabled: true   # TM 显式开启
        coordinator-service-name: crm-tx-tcc-coordinator
        coordinator-address:
        deadline-seconds: 15
      participant:
        enabled: true   # RM 显式开启
        grpc-enabled: true
        grpc-port: 9091
        try-endpoint-enabled: true
```


## 6. 深度 Review 修正

### P0：client/participant 不能默认同时开启

原来的默认值：

```text
client.enabled=true
participant.enabled=true
```

后果：

```text
TM-only 应用会加载 participant，要求 BarrierMapper/DB
RM-only 应用会加载 client，要求 Coordinator 地址/Discovery
```

已改为：

```text
client.enabled=false
participant.enabled=false
```

按角色显式开启。

## 7. 一句话

> **TCC 现在有独立 Starter，业务方不再被 Outbox/Consumer 配置绑架。**
