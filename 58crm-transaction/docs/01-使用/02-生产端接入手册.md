# 生产端接入手册

> 读完你能做什么：业务服务能正确发布 Outbox 事件，并知道哪些动作必须做、哪些绝对不能做。
> 范围：生产端；消费端尚未实现。

## 1. 业务方只做一件事

```java
outboxPublisher.publish(event);
```

前提：

```text
当前方法已经在本地事务中
业务表更新和 t_local_message 插入同一个 MySQL 事务
```

## 2. 必需的表

```sql
CREATE TABLE t_local_message (
    msg_id VARCHAR(64) NOT NULL,
    event_key VARCHAR(128) NOT NULL,
    biz_code VARCHAR(32) NOT NULL,
    biz_id VARCHAR(64) NOT NULL,
    event_type VARCHAR(64) NOT NULL,
    payload MEDIUMTEXT,
    payload_ref VARCHAR(256),
    status VARCHAR(16) NOT NULL,
    retry_count INT NOT NULL DEFAULT 0,
    next_retry_at DATETIME,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    PRIMARY KEY (msg_id),
    UNIQUE KEY uk_event_key (event_key),
    KEY idx_biz_event (biz_code, biz_id, event_type),
    KEY idx_status_retry (status, next_retry_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

要求：

```text
t_local_message 和业务表同库
payload 与 payload_ref 至少一个非空
```

## 3. 配置 bizCode 白名单

业务方配置文件示例：

```yaml
tx:
  stream-prefix: "tx:stream:"
  biz-codes:
    - lead
    - quota
    - contract
```

注意：

```text
lead/quota 只是示例
实际由业务方/Nacos 提供
框架不内置任何业务线
```

加载：

```java
Map<String, BizCodeConfig> configs = ...;
BizCodeRegistry registry = BizCodeRegistry.from(configs);
```

## 4. 生产端参数

```yaml
outbox:
  linger: 10ms
  batch-size: 256
  buffer-capacity: 50000
  buffer-capacity-bytes: 67108864
  per-biz-capacity: 10000
  per-biz-capacity-bytes: 16777216
  scan-batch: 1000
  scan-interval: 10ms
  retry-after: 30s
  max-retries: 5
  sender-threads: 8
```

含义：

```text
linger                  10ms 聚合窗口
batch-size              单批最多 256 条
buffer-capacity         最多 50000 条
buffer-capacity-bytes   最多 64MB
per-biz-capacity        单业务线最多 10000 条
per-biz-capacity-bytes  单业务线最多 16MB
scan-batch              Scanner 每轮取多少条
scan-interval           10ms 扫一次
retry-after             失败后多久再试
max-retries             超过转 DEAD
sender-threads          Sender shard 上限
```

`consumers` 不在生产配置里，属于消费端。

## 5. 业务事件

```java
BusinessEvent event = new BusinessEvent(
    "lead-assigned:lead-1:assign-001",
    "lead",
    "lead-1",
    "LEAD_ASSIGNED",
    "{\"salesId\":1001}"
);
```

字段：

```text
eventKey   业务事件唯一键
bizCode    必须已注册
bizId      业务单号
eventType  事件类型
payload    事件正文
```

## 6. 业务代码示例

```java
@Service
public class LeadAssignService {

    private final LeadRepository leadRepository;
    private final OutboxPublisher outboxPublisher;

    @Transactional
    public void assignLead(long leadId, long salesId, String requestId) {
        leadRepository.assign(leadId, salesId);

        outboxPublisher.publish(new BusinessEvent(
            "lead-assigned:" + leadId + ":" + requestId,
            "lead",
            String.valueOf(leadId),
            "LEAD_ASSIGNED",
            "{\"leadId\":" + leadId + ",\"salesId\":" + salesId + "}"
        ));
    }
}
```

必须：

```text
@Transactional 在最外层业务方法
业务写和 publish 在同一事务
```

不能：

```text
publish 后再开新事务
publish 里写 Redis
业务回滚但消息提交
```

## 7. 装配

```java
BizCodeRegistry registry = BizCodeRegistry.from(configs);

MybatisOutboxPublisher publisher =
    new MybatisOutboxPublisher(localMessageMapper, registry);

OutboxConfig config = new OutboxConfig(...);
OutboxBuffer buffer = new OutboxBuffer(
    config.bufferCapacity(), config.bufferCapacityBytes());
OutboxInFlight inFlight = new OutboxInFlight();
OutboxInterceptorChain interceptors =
    new OutboxInterceptorChain(List.of());
RedisStreamPublisher streamPublisher =
    new RedisStreamPublisherAdapter(stringRedisTemplate);

OutboxProducer producer = OutboxProducerFactory.create(
    buffer,
    streamPublisher,
    interceptors,
    new BizCodePartitioner(),
    new DefaultOutboxSerializer(),
    repository,
    inFlight,
    config,
    registry);

producer.start();
```

关闭：

```java
producer.close();
```

## 8. 发布失败会出现什么

### 未知 bizCode

```text
MybatisOutboxPublisher.publish 抛 UnknownBizCodeException
业务事务回滚
不写消息
```

### eventKey 重复

```text
MySQL 唯一键冲突
业务事务回滚
```

### 没有外层事务

```text
@Transactional(MANDATORY) 抛 IllegalTransactionStateException
```

### 消息超大

```text
publish 成功，消息写 INIT
Scanner 发现超过 buffer byte 上限
→ 直接 DEAD
```

### Stream 失败

```text
XADD 失败
→ 失败重试
→ 超过 maxRetries 转 DEAD
```

## 9. 业务方必须知道的语义

```text
至少一次，不是 exactly-once
可能重复，消费方必须幂等
不保证全局顺序
SENT 表示已写入 Stream，不代表消费成功
业务事务提交后，业务方不能撤销消息
```

## 10. 业务方不要做

```text
不要自己写 t_local_message
不要自己写 Redis Stream
不要自己实现重试调度
不要把 payload 只放 Redis
不要给同一个业务事件生成新的 eventKey
不要依赖 global FIFO
```
