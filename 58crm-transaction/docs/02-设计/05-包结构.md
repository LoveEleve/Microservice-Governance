# 包结构与依赖规则

> 读完你能做什么：知道每个包负责什么、依赖方向是什么、新增类该放哪里。

## 1. 包结构

```text
com.wuba.crm.tx.outbox
├── api
│   ├── BusinessEvent
│   └── OutboxPublisher
├── domain
│   ├── LocalMessage
│   ├── OutboxRecord
│   └── OutboxSendResult
├── config
│   ├── BizCodeConfig
│   ├── BizCodeRegistry
│   └── UnknownBizCodeException
├── persistence
│   ├── LocalMessageEntity
│   ├── LocalMessageMapper
│   ├── LocalMessageRepository
│   ├── MybatisLocalMessageRepository
│   └── MybatisOutboxPublisher
├── producer
│   ├── OutboxConfig
│   ├── OutboxBuffer
│   ├── OutboxInFlight
│   ├── OutboxScanner
│   ├── OutboxSender
│   ├── SenderAssignment
│   ├── OutboxProducer
│   ├── OutboxProducerFactory
│   └── MessageTooLargeException
└── pipeline
    ├── interceptor
    │   ├── OutboxInterceptor
    │   └── OutboxInterceptorChain
    ├── route
    │   ├── OutboxPartitioner
    │   └── BizCodePartitioner
    ├── serializer
    │   ├── OutboxSerializer
    │   └── DefaultOutboxSerializer
    └── stream
        ├── RedisStreamPublisher
        └── RedisStreamPublisherAdapter
```

## 2. 依赖方向

```text
config
  ← persistence
  ← producer

api
  ← persistence
  ← producer

domain
  ← persistence
  ← producer
  ← pipeline

pipeline
  ← producer

persistence
  ← producer
```

禁止：

```text
api 依赖 persistence
domain 依赖 Spring/MyBatis/Redis
persistence 依赖 producer
pipeline 依赖 producer
```

## 3. 各层职责

### api

业务方只依赖这一层：

```text
BusinessEvent
OutboxPublisher
```

### domain

不可变模型：

```text
LocalMessage
OutboxRecord
OutboxSendResult
```

### persistence

```text
MyBatis-Plus Entity / Mapper
Repository 接口
MyBatis 实现
OutboxPublisher 的 MySQL 实现
```

### producer

```text
Scanner
Buffer
InFlight
Sender
Producer
Config
```

### pipeline

```text
拦截器
路由
序列化
Stream 写入
```

## 4. 新增类放哪里

```text
新的业务事件字段 → domain/api
新的数据库操作 → persistence
新的发送策略 → producer
新的扩展点 → pipeline
新的 Stream 实现 → pipeline.stream
```

## 5. 测试包

```text
persistence 测试 → outbox.persistence
producer 测试 → outbox.producer
pipeline 测试 → outbox.pipeline.*
```

测试包与生产包镜像，避免测试全部堆在根包。
