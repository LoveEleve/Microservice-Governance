# 消费者模型

> 现状：消息已经进入 Redis Stream，但还没有 consumer group、XACK、PEL 和消费代码。  
> 本文讨论目标模型，不含实现代码。

## 1. 当前状态

生产端完成后：

```text
MySQL:
  t_local_message.status = SENT
  stream_entry_id = 179...-0

Redis:
  tx:stream:lead
  tx:stream:quota
  tx:stream:order
```

Redis：

```text
Redis
├── tx:stream:lead
│   ├── 179...-0 -> {msgId=m-1, bizCode=lead, ...}
│   ├── 179...-1 -> {msgId=m-2, ...}
│   └── 179...-2 -> {msgId=m-3, ...}
├── tx:stream:quota
│   ├── 179...-0 -> {msgId=m-4, ...}
│   └── 179...-1 -> {msgId=m-5, ...}
└── tx:stream:order
    └── 179...-0 -> {msgId=m-6, ...}
```

此时：

```text
没有 consumer group
没有 last-delivered-id
没有 PEL
没有 XACK
消息只是 append 在 Stream 中
```

## 2. 消费端目标模型

```text
一个业务线
一个 Stream
一个消费组
多个 consumer 竞争
```

这里消费组是 **ACK/PEL 机制**，不是多下游广播。

```text
tx:stream:lead
  └── group tx-group-lead
        ├── consumer lead-service-1
        ├── consumer lead-service-2
        └── consumer lead-service-3
```

不同业务线：

```text
tx:stream:lead  -> tx-group-lead
tx:stream:quota -> tx-group-quota
tx:stream:order -> tx-group-order
```

## 3. 消费端结构

```text
+--------------------------------------------------+
| StreamConsumer(lead)                             |
|                                                  |
| consumerId = lead-service-1                     |
| group      = tx-group-lead                      |
| stream     = tx:stream:lead                     |
+----------------------+---------------------------+
                       |
                       | XREADGROUP
                       v
+--------------------------------------------------+
| Redis Stream tx:stream:lead                      |
|                                                  |
| group tx-group-lead                              |
|   last-delivered-id                              |
|   PEL: entryId -> consumerId                     |
+----------------------+---------------------------+
                       |
                       v
+--------------------------------------------------+
| 消费方 MySQL                                     |
|                                                  |
| t_consume_record                                 |
|   msg_id / stream_entry_id / status / lease_until|
|                                                  |
| t_idempotent                                     |
|                                                  |
| 业务表                                           |
+----------------------+---------------------------+
                       |
                       | 业务事务提交成功
                       v
+--------------------------------------------------+
| XACK tx:stream:lead tx-group-lead entryId...     |
+--------------------------------------------------+
```

## 4. 启动

每个业务线启动时：

```bash
XGROUP CREATE tx:stream:lead tx-group-lead 0 MKSTREAM
```

含义：

```text
Stream 不存在 -> 创建空 Stream
group 不存在 -> 创建
group 已存在 -> BUSYGROUP，视为成功
```

如果使用 `$`：

```text
只消费创建 group 之后的新消息
历史消息不补
```

当前建议使用 `0`：

```text
已有未消费消息也进入消费组
```

## 5. 主流程

### 5.1 拉取

```bash
XREADGROUP GROUP tx-group-lead lead-service-1
  COUNT 500
  BLOCK 1000
  STREAMS tx:stream:lead '>'
```

结果：

```text
entryId1 -> fields
entryId2 -> fields
...
```

此时：

```text
消息进入 lead-service-1 的 PEL
last-delivered-id 前进
尚未 XACK
```

### 5.2 写消费记录

消费方本地 DB：

```text
t_consume_record
  msg_id
  stream_entry_id
  consumer_id
  status = PROCESSING
  lease_until
```

如果已存在：

```text
CONSUMED -> 跳过
PROCESSING 且 lease 有效 -> 跳过
PROCESSING 且 lease 过期 -> 重新处理
```

### 5.3 业务处理

```text
handler.handle(message)
```

业务事务内：

```text
业务表更新
+ t_consume_record
+ t_idempotent
```

### 5.4 提交

```text
业务事务 COMMIT
```

### 5.5 XACK

```bash
XACK tx:stream:lead tx-group-lead entryId1 entryId2 ...
```

批量确认，不是每条消息一次 RPC。

## 6. 故障流程

### 业务失败

```text
业务事务回滚
不 XACK
消息留在 PEL
```

后续：

```text
XPENDING
XCLAIM / XAUTOCLAIM
```

### 消费者崩溃

```text
consumer-1 取走消息
PEL 记录 consumer-1
进程崩溃
lease 过期
consumer-2 XCLAIM
```

### XACK 失败

```text
业务已提交
XACK 失败
消息仍在 PEL
其他 consumer 重新领取
t_consume_record = CONSUMED
业务幂等跳过
补 XACK
```

### 顺序错误

不能：

```text
先 XACK
后提交业务事务
```

否则业务回滚，消息丢失。

## 8. 消费端线程与批量

```text
每个业务线一个 StreamConsumer
  ├── XREADGROUP COUNT 500
  ├── 业务处理线程池
  └── 批量 XACK
```

建议初始参数：

```text
count = 500
block = 1000ms
lease = 30~60s
consumer 数 = 2~4 起
```

不要：

```text
一个消息一个线程
一个消息一个 ACK RPC
一个业务线阻塞所有业务线
```

## 9. 和生产端的关系

生产端：

```text
t_local_message:
  SENT
  stream_entry_id
```

消费端：

```text
t_consume_record:
  PROCESSING / CONSUMED
```

生产端不会因为 XACK 自动变成 DONE。

对账组件后续：

```text
查 SENT
查消费方 CONSUMED
→ markDoneBatch -> DONE
```
