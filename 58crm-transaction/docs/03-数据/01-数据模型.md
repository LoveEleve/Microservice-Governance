# 数据模型

> 读完你能做什么：知道每张表属于谁、主键/唯一键是什么、分片键是什么。

## 1. 数据归属

```text
协调器 MySQL：
  t_tcc_global
  t_tcc_branch

参与方业务 MySQL：
  业务表
  t_branch_barrier
  t_local_message

消费方 MySQL：
  t_idempotent
  t_message_attempt

对账库：
  t_recon_diff
```

## 2. C-001 先落三张表

```text
t_local_message
t_idempotent
t_message_attempt
```

### `t_local_message`

```text
msg_id            PK
event_key         UK
biz_code
biz_id            分片键
event_type
payload / payload_ref
status
lease_until
consumer_id
retry_count
next_retry_at
created_at
updated_at
```

必须：

```text
payload 与 payload_ref 至少一个非空
状态：INIT/SENT/PROCESSING/CONSUMED/DEAD
一条消息只有一行正本
```

### `t_idempotent`

```text
msg_id     PK
biz_key    UK
status
created_at
```

### `t_message_attempt`

```text
id          PK
msg_id
attempt_no
consumer_id
status
error_msg
created_at
UNIQUE(msg_id, attempt_no)
```

## 3. 后续 TCC 表

```text
t_tcc_global
  xid PK
  request_id UK
  biz_code/biz_id
  status
  timeout
  retry

t_tcc_branch
  xid + branch_id PK
  UNIQUE(xid, resource_key)
  status
  retry

t_branch_barrier
  xid + branch_id PK
  resource_type/resource_key
  action_name
  status
  version
  lease_until
```

## 4. 分片

```text
t_local_message：按 biz_id
t_idempotent：按 msg_id
消息查询必须带 biz_id
```

生产形态：

```text
16 库 × 4 表 = 64 分片
1 主 2 从
写主库，状态查询走从库
延迟 > 500ms 回主库
```

## 5. 索引原则

```text
状态扫描：idx_status_retry(status, next_retry_at)
业务查询：idx_biz_event(biz_code, biz_id, event_type)
幂等：uk_biz_key
消息唯一：uk_event_key
```

禁止：

```text
select * 带出 payload
无分片键全表扫描
一条消息多行正本
```
